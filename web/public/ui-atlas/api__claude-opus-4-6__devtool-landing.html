Features

Everything you need to
debug query performance

No dashboards to deploy, no agents to configure. Tern reads from your database's built-in stats and gives you answers.

Automatic Query Discovery

Reads from pg_stat_statements, performance_schema, or slow query logs. No code changes needed.

EXPLAIN Visualization

Run EXPLAIN ANALYZE and get a readable tree view with cost breakdowns, right in your terminal.

Real-time Monitoring

Watch mode streams live query stats so you can see the impact of your changes immediately.

Fix Suggestions

Get actionable index recommendations and query rewrites. Copy-paste the fix, run it, done.

CI/CD Integration

Add tern check to your pipeline. Fail builds when a migration introduces a slow query.

Single Binary

Download one file. No runtime dependencies, no Docker, no config files. Works on Linux, macOS, and Windows.

How It Works

Three commands.
Faster queries.

1

Connect to your database

Point Tern at your database using a connection string or environment variable. It uses read-only access to query statistics views.

❯ tern init --dsn "postgres://user:pass@host/db"
2

Scan for slow queries

Tern analyzes query execution statistics, identifies sequential scans, missing indexes, and N+1 patterns, then ranks them by total time impact.

❯ tern scan --threshold 50ms --format table
3

Apply the fix

Tern generates the exact SQL you need — indexes, query rewrites, or configuration changes. Review it, apply it, and watch your p99 drop.

❯ tern fix #1 --dry-run
