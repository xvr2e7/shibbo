Tern finds slow queries in Postgres, MySQL, and SQLite. It groups what your application ran, ranks each statement by total time, and names the scan, lock, or N+1 underneath.

Install Tern How it works
  • Total timeCalls × duration, not the single worst spike.
  • On the boxA log file or a database URL. Query text is not uploaded.
  • No dashboardA ranking, a statement, a cause. Then it gets out of the way.

Method

Three steps. No dashboard.

Point Tern at what your database already records. It reads, ranks, and exits.

01

Point it at a source

A database URL, a slow-query log, or a file you already exported. A scan does not need an agent living in production.

tern scan --log ./slow.log

tern watch postgres://localhost/shop

02

Group the statements

Literals fold into placeholders, so a thousand near-identical calls become one line. The score is total time — calls × mean duration — not the single worst spike.

03

Read the cause

Each finding names what Tern saw: a sequential scan, a lock wait, or a burst that looks like N+1. You choose the fix. Tern does not rewrite SQL.

Finding 01

A sequential scan, wearing a join.

The selected row, opened. Why it ranked first, and where Tern stops talking.

2.00s mean 205 calls 410s total 41% of db time

SELECT o.id, o.total, li.sku, li.qty
FROM orders o
JOIN line_items li ON li.order_id = o.id
WHERE o.created_at > $1
ORDER BY o.created_at DESC

Sequential scan on line_items. No index on order_id.

  1. Grouped. 205 calls, one shape. Literals were folded to $1, so a different timestamp on each call did not split the ranking.
  2. Weighted. 2.00 seconds × 205 calls = 410 seconds. That is 41% of the 1,000 seconds of statement time in the window. A 4-second query run twice costs 8 seconds and would not surface.
  3. Named. Tern stops at the cause. It will not hand you a CREATE INDEX and pretend that is always the fix.

Rule of thumb

Average latency is a polite lie.

Total time is the bill.

Spec

A small tool, on purpose.

What Tern will commit to, and what it refuses to pretend.

Input
pg_stat_statements, the MySQL slow log, Postgres logs, or a text file you already have.
Engines
Postgres and MySQL from a URL or a slow log. SQLite from the database file.
Grouping
Normalized SQL. Literal values fold to $1 so repeated calls count as one statement.
Score
Total time: calls × mean duration. Lock wait is shown apart from execution, so a blocked update is not mistaken for a slow plan.
Output
A terminal ranking. Pass --json if a script should read the same findings.
Privacy
A local binary. Query text stays on the machine that ran the scan.

Tern only ranks statements it saw, with the timings the server recorded. It will not invent an index, and it will not explain a query that never ran.

Install

Run it where the logs are.

A static binary for macOS, Linux, and Windows, or Homebrew. No account.

Install

$brew install tern

Scan a log

$tern scan --log ./slow.log

Watch a database

$tern watch postgres://localhost/shop

A scan reads and exits. Nothing has to stay running.

Tern is named for the bird that dives on one fish, not the school.
