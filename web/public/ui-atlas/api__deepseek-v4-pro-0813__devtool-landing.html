Features

Everything you need to keep your queries fast

Tern works with your existing database — no schema changes, no invasive agents, and zero production overhead.

🔍

Automatic query profiling

Continuously profiles every query against your database and automatically flags the ones crossing your latency thresholds. No manual tracing or sampling.

🗂️

Multi-database support

Native support for PostgreSQL, MySQL, and SQLite — with more adapters on the way. Connect via URL, config file, or environment variables.

📊

Visual explain plans

Export interactive explain plans for every slow query. See exactly which indexes are missing and where sequential scans are wasting CPU.

🚨

CI-ready integration

Run Tern in your CI pipeline to catch slow queries before they hit production. Fails the build when query performance regresses.

🔒

Read-only & safe

Tern only runs EXPLAIN and system catalog queries. It never modifies your data, never adds triggers, and never impacts transaction throughput.

📝

Actionable suggestions

Every finding comes with a concrete fix: index recommendations, query rewrites, VACUUM schedules, and partitioning strategies — ready to apply.

How it works

Three steps to faster queries

Get from zero to actionable insights in under a minute.

1

Install Tern

Install via npm, Homebrew, or download a single static binary. No dependencies required.

npm install -g tern-cli
2

Run the analyzer

Point Tern at your database and let it profile your query logs, pg_stat_statements, or slow query log.

tern analyze --db postgres://...
3

Apply the fixes

Open the generated report, apply the suggested indexes and rewrites, and watch your p99 drop.

tern report --open
