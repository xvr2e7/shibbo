Principles

A chart is a sentence.

The API is small on purpose. These are the ideas it will not trade away.

  1. 01

    Marks, not a settings object

    Each series is a mark with its own encoding. A line, an area, and a target rule can share a chart without a chart-type string deciding what is allowed.

  2. 02

    SVG or canvas, same spec

    Design against the DOM, then switch renderers when a page holds more points than the DOM wants. Themes, axes, and tooltips stay put.

  3. 03

    Scales you can trust

    Continuous, band, point, log, time, and threshold. Bars include zero unless you override it. Lines do not get a zero baseline forced on them.

  4. 04

    Color that yields to CSS

    Palettes are custom properties. A theme is a class on a parent. The chart does not keep a second copy of your design tokens.

  5. 05

    Interaction that stays in sync

    Hover, focus, and brush read the same encodings as the marks. A tooltip cannot drift from the series it describes.

  6. 06

    Accessible by default

    A title becomes the chart name. Series are not identified by color alone. Focus stops land on interactive marks, and a data table is one flag away.

Marks

A mark for every shape of data.

Start with a mark, not a chart-type enum. Compose them when one series is not the whole story.

Line

Trends over a continuous domain.

Area

Volume under a curve, or a band between two.

Bar

Compare discrete categories. Zero stays in frame.

Stacked bar

Parts within a total, still on a shared baseline.

Point

Two measures, and a size if you have a third.

Heatmap

Density across two bands. Color is not the only label.

Arc

Share of a whole, when a bar would be honester and you still want the ring.

Candle

Open, high, low, close. Wicks included.

Examples

Less ceremony.

The same filled line, written two ways. Meridian keeps the encodings in the mark, not in a nested options tree.

Option object

legacy.js
new LegacyChart("#el", {
  type: "line",
  data: {
    labels,
    datasets: [{
      data,
      fill: true,
      tension: 0.3,
      borderWidth: 2,
      pointRadius: 0
    }]
  },
  options: {
    plugins: { legend: { display: false } },
    scales: {
      y: { beginAtZero: false, grid: { color: "#eee" } }
    },
    interaction: { mode: "index", intersect: false }
  }
});

Meridian

revenue.js
import { chart, line, area } from "@meridian/charts";

chart("#el", { data, x: "month", y: "amount" })
  .mark(area({ opacity: 0.12 }))
  .mark(line())
  .render();
revenue.js
import { chart, line, area } from "@meridian/charts";

const revenue = chart("#revenue", {
  data: monthly,
  x: "month",
  y: "amount",
  title: "Trailing revenue"
});

revenue
  .mark(area({ fill: "var(--ink)", opacity: 0.08 }))
  .mark(line({ strokeWidth: 2 }))
  .render();
channels.js
import { chart, bar } from "@meridian/charts";

chart("#channels", {
  data: signups,
  x: "channel",
  y: "count"
})
  .mark(bar({ fill: "var(--accent)", radius: 4 }))
  .render();
cohorts.js
import { chart, point } from "@meridian/charts";

chart("#cohorts", {
  data: cohorts,
  x: "tenure",
  y: "retention"
})
  .mark(point({ r: "size", fill: "segment" }))
  .render();

Guide

Up and rendering.

Three steps. The first chart is a line over an array of objects. No stylesheet to import.

  1. 01

    Install

    One package. No peer dependencies. The CDN build is the same API, attached as window.Meridian.

    npm install @meridian/charts
  2. 02

    Give it a node

    The chart fills its parent. Set a height in CSS. The title you pass later becomes the accessible name.

    <div id="revenue"></div>
  3. 03

    Add marks

    Data is an array of objects. Encodings name fields. Call render once the marks are declared.

    chart("#revenue", { data, x: "month", y: "amount" })
  .mark(line())
  .render();

Release

v3.1

The canvas renderer is stable. Facets take the same mark list as the root chart. Breaking change: chart.layers is now chart.marks. Encodings and scale names are unchanged.

Meridian is released under the MIT license. Keep the copyright notice if you redistribute it.

Bugs belong in issues. Design changes start as a short note in discussions, so the API does not grow a second settings object by accident. Questions about a chart you are stuck on are welcome there too.
