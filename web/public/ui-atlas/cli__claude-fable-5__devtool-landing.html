Features

Your database is talking.
Tern listens.

Everything you need to go from "the app feels slow" to a merged fix — without leaving your terminal.

Ranked by real impact

Tern weighs latency against call frequency, so you fix the query costing you the most total time — not just the slowest one-off.

Actionable fixes, not graphs

Every finding ships with a concrete remedy: the exact index to create, the join to rewrite, or the N+1 to batch — with estimated speedup.

Nothing leaves your network

Tern reads query statistics directly from your database and runs entirely on your machine. No agents, no SaaS, no data exfiltration.

Regression tracking

Snapshot performance with tern baseline and get alerted when a deploy makes a query slower than it was yesterday.

CI-friendly

Fail the build when a pull request introduces a sequential scan or unindexed query. tern check --ci returns proper exit codes and JSON.

Explains the plan

Dig into any finding with tern explain — an annotated, human-readable query plan that highlights exactly where time is spent.

Works with PostgreSQL MySQL MariaDB SQLite Amazon RDS Cloud SQL
How it works

Three commands to a faster database

1

Connect

Point Tern at any database you can reach. It reads built-in statistics views — no extensions to install, no schema changes.

$ tern connect $DATABASE_URL
2

Scan

Tern analyzes execution history, clusters similar queries, and ranks offenders by their share of total database time.

$ tern scan --last 24h
3

Fix

Apply the suggested index or rewrite, then verify the win. Tern re-measures and shows you the before-and-after.

$ tern verify
