How it works

From “something’s slow” to a fix in under a minute.

Tern doesn’t sit in your request path or ask you to instrument code. It reads what your database already knows.

1

Point it at a database

Give Tern a connection string. It uses read-only access to pg_stat_statements, performance_schema or the SQLite trace hook. Nothing is installed server-side.

2

Rank by real cost

Queries are fingerprinted so id = 4 and id = 9 count as one. Tern ranks by total time, not just the worst single run, so you fix what matters.

3

Get the fix, not just the number

Tern runs EXPLAIN on the worst offenders, spots seq scans, missing indexes and bad join orders, and prints a statement you can paste.

Features

Small tool. Sharp edges.

Explains why, not just which

Every slow query comes with its plan, annotated. Tern points to the node that costs the most and says what would change it.

Seq Scan on orders  cost=0..48211  rows=2.1M
  Filter: (customer_id = $1)
  Rows removed: 2,099,988
→ index on (customer_id) would skip 99.9%

A performance budget for CI

Fail the build when a migration or a new query pushes a fingerprint past your limit. Exit codes and JSON output included.

$ tern check --budget 200ms
✗ 2 queries over budget
exit code 1

Diff two moments in time

Snapshot before a deploy, compare after. Tern shows which queries got slower, which are new, and which disappeared.

$ tern diff before.json after.json
▲ +312%  SELECT … FROM events …
▼  −88%  SELECT * FROM orders …
＋ new   UPDATE carts SET …

Read-only. Local. Yours.

Tern never writes to your database and never phones home. Literal values are stripped before anything is printed, so secrets in WHERE clauses stay out of your terminal history and logs.

connection: read-only
telemetry:  none
literals:   redacted
Get started

Install in ten seconds. Scan in ten more.

A single static binary for macOS, Linux and Windows. Free and open source under the MIT license.

$ brew install tern

$ curl -fsSL https://tern.dev/install.sh | sh
Installs to ~/.local/bin. Read the script first if you like; it’s short.
$ cargo install tern-cli
Builds from source. Requires Rust 1.74 or newer.
FAQ

Questions, answered.

Will it slow down my production database?

Tern reads statistics tables your database already maintains, so a scan is a handful of lightweight queries. EXPLAIN is run without ANALYZE by default, meaning queries are planned but never executed.

What permissions does it need?

A read-only role. On Postgres that’s pg_monitor plus SELECT on the tables you want planned. The docs include a ready-made role script for each supported database.

Does it send my queries anywhere?

No. Tern runs entirely on your machine and has no telemetry. Output is yours to keep, pipe or commit.

How is this different from my APM or a slow query log?

Slow query logs only catch queries over a threshold, and APMs only see what you instrument. Tern aggregates every call from the database’s own counters, so a 40ms query that runs a million times shows up above a 3s query that ran once.

Can I use it with managed databases?

Yes. Anything that exposes pg_stat_statements or performance_schema works, including RDS, Cloud SQL, Supabase and Neon.
