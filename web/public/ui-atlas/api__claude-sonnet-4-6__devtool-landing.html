How it works

Zero friction, instant insight

Point Tern at any database and get actionable performance data in seconds — no agents, no dashboards, no config files.

01

Connect

Pass a DSN string on the command line or via environment variable. Tern supports PostgreSQL, MySQL, and SQLite out of the box.

02

Analyze

Tern hooks into pg_stat_statements (or the equivalent) and runs EXPLAIN ANALYZE on live queries above your threshold.

03

Surface

Results stream into a clean, sortable table with execution plans, row counts, lock info, and an index-suggestion engine built in.

04

Fix & verify

Use tern explain <query-id> to deep-dive, then re-run to confirm the speedup. Export reports as JSON or CSV for the team.

Features

Everything you need, nothing you don't

🔍

Real-time query watching

Stream slow queries as they happen, with configurable latency thresholds and call-count filters.

⚡

Automatic EXPLAIN plans

Tern runs EXPLAIN (ANALYZE, BUFFERS) automatically and formats plans into human-readable trees.

🗂️

Index suggestions

Detects sequential scans and nested-loop joins, then suggests the exact CREATE INDEX statements to fix them.

📊

Historical snapshots

Compare query performance across deploys using the built-in snapshot store. See before/after in one diff.

🔔

Threshold alerts

Pipe alerts to Slack, PagerDuty, or any webhook when queries exceed critical latency or frequency limits.

🗄️

Multi-database support

Postgres, MySQL 8+, MariaDB, and SQLite. Same CLI interface regardless of which engine you're running.

Install

Up and running in 30 seconds

Single binary. No runtime dependencies. Works anywhere Go runs.

$ brew install ternhq/tap/tern
$ curl -sSfL https://get.tern.dev | sh
$ go install github.com/ternhq/tern@latest
$ docker run --rm ghcr.io/ternhq/tern watch --dsn $DSN
Reference

CLI flags

All flags can also be set via environment variables prefixed with TERN_.

Flag Default Description
--dsn $DATABASE_URL Database connection string. Supports Postgres, MySQL, and SQLite URIs.
--threshold 500ms Minimum query duration to report. Accepts ms, s, or m suffixes.
--limit 25 Maximum number of queries to show in top and report modes.
--sort avg_time Sort key: avg_time, total_time, calls, or rows.
--format table Output format: table, json, or csv.
--interval 2s Polling interval for watch mode.
--explain false Automatically run EXPLAIN ANALYZE on detected slow queries.
--suggest-indexes false Enable the index suggestion engine. Prints CREATE INDEX recommendations.
--alert-webhook — POST slow query events as JSON to this URL (Slack, PagerDuty, etc.).
--snapshot — Save a performance snapshot to a file for later diffing with tern diff.
