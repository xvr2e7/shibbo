What it does

Everything you need to kill
a slow query. Nothing else.

Tern reads your database's own statistics — pg_stat_statements, performance_schema, the slow query log — and turns them into a ranked, actionable to-do list.

Ranked by real cost

Sort by mean latency, total wall-clock burn, p99 spikes, or rows examined. Tern weights everything by how often a query actually runs — not just how slow it is once.

tern scan --sort total-time

Plans, explained plainly

Tern parses EXPLAIN ANALYZE output and calls out the node that hurts: a sequential scan over 900k rows, a nested loop that explodes, a sort spilling to disk.

tern explain "…" --annotate

Index suggestions

Generates the exact CREATE INDEX CONCURRENTLY statement, estimates the speedup, and checks it won't collide with indexes you already have.

tern fix --dry-run

Live watch mode

Tail your database like a log file. Every query over your threshold surfaces instantly with duration, rows touched, and the app route it came from.

tern watch --threshold 200ms

Regressions in CI

Commit a baseline. Tern fails your build when a new query exceeds the p99 budget or when a migration adds a full scan — before it reaches production.

tern check --baseline main

Read-only & safe

Tern never writes to your database unless you explicitly run fix. It works over a read replica, needs no agent, and ships as a single 9MB binary.

--read-only by default
Three commands

From “the app feels slow”
to a merged migration.

Tern fits in the workflow you already have: your terminal, your shell history, your pull requests.

1

Point it at your database

Any connection string works. Tern reads query statistics read-only and starts sampling immediately — no schema changes, no extensions to install.

$ tern scan --db $DATABASE_URL ✓ 18,204 queries analyzed in 3.2s ⚠ 3 slow queries found
2

Drill into the one that hurts

Ask Tern about a single query. It runs the plan, annotates the expensive node, and reports how many rows were scanned and thrown away.

$ tern explain 1 Seq Scan on orders (rows=12,431) ⚠ 887k rows discarded by filter
3

Ship the fix

Tern writes the migration, estimates the improvement, and hands you a file you can put straight into a pull request.

$ tern fix --out migrations/ ✓ wrote 0007_add_orders_user_idx.sql ✓ est. 98.7% faster · 1.8s → 24ms
