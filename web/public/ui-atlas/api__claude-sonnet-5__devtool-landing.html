Features

Everything you need, nothing you have to configure.

Tern plugs into your existing database — no agents, no sidecars, no schema changes. Just a binary and a connection string.

Live query profiling

Stream real production traffic and rank queries by total time, call count, or average latency as it happens.

Automatic EXPLAIN

Tern re-runs flagged queries through the planner and highlights sequential scans, bad joins, and missing indexes.

Index suggestions

Get concrete, copy-pasteable CREATE INDEX statements with estimated speedups before you run them.

Trend tracking

Snapshot query performance over time and get alerted the moment a query's p95 regresses after a deploy.

CI gate

Run tern ci in your pipeline to fail builds that introduce queries slower than a defined budget.

Read-only by default

Tern never writes to your database. It observes via connection stats and sampled query logs, safely.

How it works

From install to insight in under two minutes.

No dashboards to deploy, no credentials to hand out beyond read access. Tern runs entirely from your terminal.

01

Connect

Point Tern at your database with a connection string: tern connect $DATABASE_URL. Works over SSH tunnels and read replicas too.

02

Watch

Run tern watch to sample live traffic, or tern scan to analyze historical logs from pg_stat_statements or slow-query logs.

03

Fix

Drill into any query with tern explain to see the plan, cost breakdown, and a suggested index or rewrite.

tern explain 1

Query:

SELECT * FROM orders WHERE user_id = $1

 

Plan:

Seq Scan on orders (cost=0.00..48210.00 rows=12 width=312)

Filter: user_id = $1

Rows removed by filter: 1,204,811

 

Fix → CREATE INDEX idx_orders_user_id ON orders(user_id);

Projected cost: 0.42..8.60 (38x faster)

No guesswork

Stop reading query plans by hand.

Tern parses the plan tree for you and translates it into plain-language findings — then proposes the exact fix, with the estimated impact before you touch production.

  • Plain-language diagnostics — "sequential scan on 1.2M rows" instead of raw cost numbers.
  • Ready-to-run index DDL — copy, paste, done. No index math required.
  • Before/after cost estimates — know the win before you commit to a migration.
