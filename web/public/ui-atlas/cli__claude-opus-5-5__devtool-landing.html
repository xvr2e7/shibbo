// how it works

Three commands to a faster database.

01

Connect

Hand Tern a connection string. It checks which stats sources are enabled and tells you if anything is missing.

$ tern connect $DATABASE_URL ✓ pg_stat_statements enabled ✓ read-only role detected saved profile "shop-prod"
02

Rank

Tern normalizes every query into a shape, groups them, and sorts by total time spent. The real culprits float to the top.

$ tern top --since 24h --limit 3 # TOTAL CALLS P95 QUERY 1 38.2m 1.9M 61ms SELECT … FROM orders 2 11.4m 220k 48ms UPDATE carts SET … 3 4.1m 12 20.5s SELECT … report_daily
03

Fix

Ask Tern why a query is slow. It reads the plan, explains it in plain English, and estimates the win before you change anything.

$ tern explain 1 ! Seq Scan on orders (4.2M rows) filter: customer_id = $1 → CREATE INDEX CONCURRENTLY ON orders (customer_id); est. p95 61ms → 0.8ms

// faq

Questions, answered.

Still curious? Open an issue on GitHub. Maintainers usually reply within a day.

Is it safe to point Tern at production?

Yes. Tern only reads from statistics views like pg_stat_statements and performance_schema. It never proxies traffic, and explain runs plans without executing them unless you pass --analyze.

Does Tern see my data?

Query text is normalized and every literal is replaced with a placeholder before it's stored or displayed. Row data is never read.

What do I need to enable on my database?

For Postgres, the pg_stat_statements extension. For MySQL and MariaDB, performance_schema. Run tern doctor and it'll tell you exactly what's missing and how to turn it on.

Can I use it with an ORM?

Absolutely. Tern works at the database level, so it doesn't matter whether queries come from Rails, Django, Prisma, or hand-written SQL. It's particularly good at catching ORM-generated N+1 patterns.

Which platforms are supported?

macOS (Intel and Apple Silicon), Linux (x86_64 and arm64), and Windows. Install via Homebrew, apt, Scoop, cargo install tern-cli, or grab a binary from the releases page.
