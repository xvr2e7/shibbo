Features

Stop guessing which query is the problem.

Tern ranks queries by the time they actually cost you, then reads the execution plan so you don't have to.

01

Ranked by real impact

Queries are sorted by total time consumed, not just worst-case latency, so you fix what matters first.

02

Plain-English diagnosis

Tern reads EXPLAIN output and tells you what's wrong: sequential scans, missing indexes, disk sorts, bad joins.

03

Copy-paste fixes

Get concrete suggestions like index definitions and query rewrites, with an estimated improvement for each.

04

N+1 detection

Spots repeated queries fired in loops and points to the call site in your code.

05

CI-friendly

Use tern diff and exit codes to fail a pull request when a new query regresses past your threshold.

06

Safe by default

Read-only connections, no data leaves your machine, and query parameters are redacted from output.

How it works

From install to answer in three commands.

Install

A single static binary for macOS and Linux.

brew install tern

Point it at your database

Tern uses your existing query stats. Nothing to enable on the app side.

tern scan --db $DATABASE_URL

Fix and verify

Apply a suggestion, then re-run to confirm the win.

tern diff --since 1h
Compatibility

Works with the databases you already run.

Tern connects directly using standard statistics views and plan output.
