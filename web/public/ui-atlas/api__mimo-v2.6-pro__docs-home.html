Why Ridgeline

Everything a serious chart needs. Nothing it doesn't.

A small, composable core with a rendering pipeline built for real-world data — typed end to end, accessible by default, and themeable down to the last tick.

Fast where it counts

A retained-mode scene graph, adaptive path sampling and off-thread layout let Ridgeline render a million points without dropping a frame — on a phone.

renderer · webgl2

Accessible by default

Every chart ships with a generated data table, ARIA labelling, keyboard navigation between marks, and contrast-safe palettes that meet WCAG 2.2 AA — no extra work required from your team.

aria keyboard screen reader reduced motion

Composable marks

Build any chart from a handful of primitives — lines, areas, bars, bands, points and annotations — that share scales and interactions.

Typed end to end

Generics flow from your data shape to the tooltip formatter. If it compiles, the chart renders — full inference, zero casts.

Design-token theming

Bind scales, typography and spacing to your own tokens. Light, dark and print variants fall out of one source of truth.

One syntax. Four frameworks. No wrappers.

The same declarative config drives the vanilla core and every official binding. Charts are portable between teams, frameworks and even to static export — ridgeline export writes SVG or PNG straight from CI.

Get started

From install to first chart in under a minute.

No build configuration, no peer-dependency puzzles, no wrapper components to learn. Add the package, describe your chart, render it.

1

Install the core and your binding

The core is framework-agnostic and 12.4 KB gzipped. Bindings add about 1.8 KB each and re-export the same API.

2

Describe your chart declaratively

Pass your data, the channels to plot, and any options you want to override. Everything else uses sensible, design-reviewed defaults.

3

Style it with your tokens

Swap the built-in theme for your own, or just change two colours. Ridgeline resolves everything through CSS custom properties at render time.

4

Add interaction when you need it

Tooltips, brush selection, zoom and crosshairs are opt-in plugins. They share one event pipeline, so nothing double-binds.

Write it your way

The same chart in every framework.

Identical options, identical output. Move a chart between codebases without rewriting a single line of configuration. 

// RevenueChart.tsx
import { Chart, Area, Line, Axis } from '@ridgeline/react';

export function RevenueChart({ revenue }: Props) {
  return (
    <Chart
      data={revenue}
      x="quarter"
      height={320}
      theme="auto"
    >
      <Area y="recurring" smooth={0.32} fill="url(#grad)" />
      <Line  y="usage" stroke="#FF7A45" dash={4} />
      <Axis position="bottom" ticks="quarter" />
      <Tooltip shared format={usd} />
    </Chart>
  );
}
<!-- RevenueChart.vue -->
<template>
  <Chart :data="revenue" x="quarter" :height="320" theme="auto">
    <Area y="recurring" :smooth="0.32" fill="url(#grad)" />
    <Line y="usage" stroke="#FF7A45" :dash="4" />
    <Axis position="bottom" ticks="quarter" />
    <Tooltip shared :format="usd" />
  </Chart>
</template>
<!-- RevenueChart.svelte -->
<script lang="ts">
  import { Chart, Area, Line, Axis } from '@ridgeline/svelte';
  export let revenue: Row[];
</script>

<Chart data={revenue} x="quarter" height={320}>
  <Area y="recurring" smooth={0.32} />
  <Line y="usage" stroke="#FF7A45" />
</Chart>
// main.ts
import { chart, Area, Line, Axis } from '@ridgeline/core';

const view = chart('#app', {
  data: revenue,
  x: 'quarter',
  height: 320,
  theme: 'auto',
  marks: [
    new Area({ y: 'recurring', smooth: 0.32 }),
    new Line({  y: 'usage', stroke: '#FF7A45' }),
    new Axis({ position: 'bottom', ticks: 'quarter' }),
  ],
});

view.render();
