Features

Built for engineers who live in the terminal.

No agents to deploy, no dashboards to log into. Just a binary, a connection string, and answers.

⚡

Zero configuration

Point it at a connection string and go. Tern reads what it needs from your database's own statistics views.

⇅

Ranked by impact

Queries are grouped by normalized fingerprint and sorted by total time spent, so you fix the things that matter first.

◎

Index suggestions

Tern analyzes query plans and proposes specific indexes, with estimated impact, ready to review and apply.

⎋

Read-only by default

Tern only reads statistics and EXPLAIN output. It never writes to your database unless you explicitly ask it to.

{ }

Scriptable output

Emit JSON, CSV, or plain text. Fail CI builds when a query regresses past a threshold you set.

◐

Single static binary

Written in Go. No runtime, no dependencies, works on macOS, Linux, and Windows.

How it works

From connection string to fix in four steps.

Tern is designed to be run ad hoc during an incident or as a scheduled check in your pipeline.

Install

Grab the binary with Homebrew or the install script.

brew install tern

Connect

Pass a connection string. Credentials can come from env vars.

export TERN_DSN=postgres://…

Scan

Tern samples recent activity and normalizes every statement.

tern scan --window 15m

Fix

Review suggested indexes and apply the ones you trust.

tern suggest --apply=false

FAQ

Questions, answered.

Still curious? Open an issue on GitHub and we'll get back to you.

Does Tern modify my data?

No. Tern is read-only by default. It queries statistics views such as pg_stat_statements and runs EXPLAIN to analyze plans. Any change, including applying a suggested index, requires an explicit flag.

Do I need to install an extension?

For the best results, enable pg_stat_statements on PostgreSQL or the performance schema on MySQL. Tern will tell you if something is missing and how to turn it on, but it can fall back to log parsing if needed.

Is it safe to run against production?

Tern runs a small number of lightweight catalog and statistics queries with a short statement timeout. It doesn't hold locks and adds negligible load. Pointing it at a read replica is still the most cautious option.

How are queries grouped?

Tern normalizes literals and parameters so that WHERE id = 42 and WHERE id = 99 collapse into a single fingerprint, then ranks fingerprints by total time spent.

Can I use it in CI?

Yes. Use --format json and --fail-above to fail a build when a query's p95 latency exceeds your threshold.
