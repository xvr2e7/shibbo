Find the slow queries hiding in your database.

Tern is a command-line tool that reads your Postgres and MySQL query statistics, ranks the worst offenders by total cost, and tells you why each one is slow.

Features

Built for the terminal you already live in

No agents, no dashboards to log into, no data leaving your machine. Just answers.

{}

Reads what you already have

Works with pg_stat_statements, the MySQL slow query log, and performance_schema. Nothing new to install on your database.

#

Ranked by real cost

Queries are sorted by total time spent, not just the single slowest run. The expensive query that runs a million times shows up first.

//

Explains the why

Tern spots sequential scans, stale statistics, lock contention, and N+1 patterns, then suggests the specific index or fix.

Δ

Catches regressions

Run tern diff between two deploys or time windows to see exactly which queries got slower and by how much.

[]

Redacts by default

Literal values are stripped before anything is printed or saved. Your customer emails and tokens stay out of your reports.

>_

Scriptable output

Pass --json or --format csv to pipe results into jq, a spreadsheet, or your own tooling.

How it works

Three commands from install to insight

01 / CONNECT

Point it at a database

Give Tern a connection string. It only needs read access to the stats views.

export TERN_DB=postgres://ro@db/app
02 / SCAN

Rank the offenders

Tern pulls query statistics for your chosen time window and groups similar statements together.

tern scan --since 24h --top 10
03 / FIX

Act on the advice

Each hot spot comes with an explanation and a suggested change you can review and apply.

tern explain 3 --suggest
Commands

A small surface area

Four commands cover almost everything you'll do with Tern.

tern scan Rank the slowest queries in a time window and show likely causes.
tern explain <rank> Show the query plan, detected problems, and suggested fixes for one query.
tern diff <a> <b> Compare two saved reports and highlight queries that regressed or improved.
tern check Fail with a non-zero exit code when any query exceeds your thresholds.

CI integration

Stop slow queries before they ship

Add tern check to your pipeline. It compares the current run against your budget and fails the build if any query goes over its limit.

# .github/workflows/db.yml
- run: tern check \
    --max-avg 200ms \
    --max-total 30m \
    --since 1h
# exit 1 if any query is over budget
