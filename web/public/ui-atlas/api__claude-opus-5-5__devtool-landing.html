// FEATURES

Your database already knows what's slow. Tern makes it say so.

No agents, no sidecars, no SDK to wire into your app. Point it at a connection string and get answers in seconds.

Ranked by real cost

Sorts by total time, not just the slowest single call. The 4ms query run 2M times a day shows up first, as it should.

Plans, explained

Runs EXPLAIN safely on a replica and translates seq scans, nested loops, and spills into plain language.

Index suggestions

Proposes the exact CREATE INDEX to run, estimates the speedup, and flags indexes you're paying for but never use.

Query fingerprinting

Groups thousands of near-identical statements by shape, so WHERE id = 7 and = 8 count as one.

Regressions in CI

tern check fails the build when a migration or ORM change makes a hot query worse. Catch it before deploy.

Read-only by design

Never writes to your database. Parameters are redacted by default, and nothing leaves your machine unless you ask.

// HOW IT WORKS

From "it feels slow" to a fix in three commands.

  1. Connect

    Use any connection string, or let Tern read DATABASE_URL. A read replica works great.

    $ tern connect $DATABASE_URL

  2. Scan

    Tern reads pg_stat_statements, performance_schema, or the slow log, then fingerprints and ranks every query.

    $ tern scan --since 24h --top 10

  3. Explain & fix

    Drill into any query to see its plan, the bottleneck, and a suggested change with an estimated speedup.

    $ tern explain 1 --suggest

// FAQ

Questions, answered.

Is it safe to run against production?

Yes. Tern only issues read-only statements and runs EXPLAIN without ANALYZE unless you pass --analyze. We still recommend pointing it at a replica for the deepest inspections.

What do I need enabled on my database?

For Postgres, the pg_stat_statements extension. For MySQL and MariaDB, performance_schema (on by default) or the slow query log. SQLite works by replaying a captured query trace. Run tern doctor and it'll tell you exactly what's missing.

Does any data leave my machine?

Not with the free CLI. Query parameters are redacted locally by default. Tern Team uploads only fingerprinted, parameter-free query shapes and timing statistics, and you can self-host the server.

How is this different from an APM?

APMs tell you a request was slow. Tern tells you which query, why the planner chose what it did, and what index or rewrite will fix it. Many teams use both: the APM to notice, Tern to diagnose.

Can I use it with an ORM?

Absolutely. Tern works at the database level, so it sees exactly what Prisma, ActiveRecord, SQLAlchemy, or GORM actually sends, N+1 patterns included.
