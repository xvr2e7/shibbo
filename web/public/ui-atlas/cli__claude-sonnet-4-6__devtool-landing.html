How Tern works

No agents, no sidecars, no config files unless you want them.

01

Connect with a DSN

Pass your database URL and Tern opens a single read-only connection. Works with any standard connection string.

02

Sample or profile

Tern reads from pg_stat_statements, slow query logs, or performs live sampling — whichever is available.

03

Rank and explain

Queries are ranked by total wall time, then individually EXPLAINed to identify the root cause.

04

Output your way

Print a human-readable table, emit JSON for tooling, or generate a Markdown report to drop into a PR.

tern explain
$ tern explain --query-id q_8f3a
 
Query
SELECT * FROM orders
WHERE user_id = $1 AND status = 'pending'
 
Execution Plan
Seq Scan on orders (cost=0.00..48291.00)
Filter: (user_id = $1 AND status = 'pending')
Rows removed by filter: 1,204,381
 
Diagnosis
✗ Full sequential scan on 1.2M rows
✗ No usable index for this predicate
 
Suggested fix
CREATE INDEX CONCURRENTLY idx_orders_user_status
ON orders (user_id, status)
WHERE status = 'pending';
 
Est. speedup: ~180× (12ms → 0.07ms)
