What it does

Everything you need to find the culprit

Tern is opinionated about one thing: showing you the queries that matter, in the order they hurt.

Query fingerprinting

Tern normalizes literals and parameters, so 40,000 near-identical statements collapse into a single row you can actually reason about.

EXPLAIN, decoded

Plans are rendered as a tree with the expensive node highlighted — no more squinting at a wall of nested JSON.

N+1 detection

Tern correlates queries by request and flags the ORM loops that fire hundreds of statements where one would do.

Live tail

Follow slow queries as they happen against staging or production. Filter by table, duration, or the service that issued them.

CI budgets

tern check --budget 200ms exits non-zero the moment a query regresses. Performance stops being a vibe.

Zero-config install

One static binary. No agent, no daemon, no sidecar, no schema changes. Point it at a DSN and it starts working.

How it works

Three commands from mystery to fix

Tern reads the same wire traffic your database already sees. Nothing to instrument, nothing to redeploy.

Point it at a DSN

Any Postgres, MySQL or SQLite connection string. Tern attaches read-only and starts sampling immediately.

$ tern watch --dsn $DATABASE_URL

Read the ranked list

Queries are fingerprinted and ranked by total time — so you fix the one query costing you 40% of your p95, not the one that merely looks scary.

$ tern top --since 1h --limit 10

Lock it in

Set a budget and let CI enforce it. Regressions get caught in review instead of in an incident channel.

$ tern check --budget 200ms --p95 ✓ 34 fingerprints within budget
