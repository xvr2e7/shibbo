Why Tern

Your database is slow somewhere. Tern tells you where.

APMs tell you a request took 900ms. Tern tells you which of the 4,000 statements behind it deserves your afternoon.

Statement-level ranking

Every query is fingerprinted and timed. Tern groups identical shapes into one row so /orders?since= shows up once, not 4,000 times.

Cost, not just time

Rows scanned vs. rows returned, buffer hits vs. reads, temp spills. Tern surfaces the queries doing 100× more work than they need to.

Actionable fixes

Not "this query is slow" — but CREATE INDEX CONCURRENTLY ON orders (created_at DESC), with a measured before/after delta.

EXPLAIN plan diffing

Tern captures the plan before and after your change and highlights the node that flipped from Index Scan to Seq Scan.

CI regression gates

Commit a tern.yml baseline and let Tern fail the build when a query crosses your latency budget. Your ORM's new includes() won't ship at 2am.

Zero install footprint

One static binary. It talks to your database like your app does — no kernel module, no sidecar, no daemon left running. Read-only credentials work fine.

How it works

Three commands. Zero instrumentation.

Point it at a database

Give Tern a connection string, or point it at your app's DATABASE_URL. Read-only is enough.

Let it observe

Run it against staging, replay a traffic shape, or point your test suite at a throwaway database. Tern fingerprints and times every statement.

Fix the top 5

Get a ranked report with concrete index and rewrite suggestions — plus the expected speedup for each one.

The report

Plain text. Machine-readable. Zero dashboards.

Tern prints a ranked report to your terminal — and emits JSON, CSV, or SARIF when you need it somewhere else.

Ranked by total time wasted, not by p99 — one slow query called 40,000 times beats a slower query called twice.
Each row carries the estimated time saved if you apply the suggested fix.
Flags N+1 patterns, missing LIMIT, and accidental sequential scans automatically.
Diff two runs to see what your last deploy actually did to the database.

Install

Running in under a minute

No runtime dependencies. Static binaries for macOS, Linux, and Windows.

$ npm install -g @tern/cli

Includes shell completions for bash, zsh, fish and PowerShell.

$ brew install tern

Also available as tern-beta on the tap for nightly builds.

$ cargo install tern-cli --locked

Builds from source in ~90s with a stable toolchain. Requires Rust 1.74+.

$ docker run --rm -it terndev/tern --url $DATABASE_URL

Image is 14MB, distroless, runs as a non-root user.

$ curl -fsSL https://tern.sh/install.sh | sh

Installs to ~/.tern/bin. Verify with tern --version.

FAQ

Questions engineers actually ask

Does Tern need production access?
No. Tern is designed for staging, CI, and read-replicas. It only needs a connection string and a read-only role. If you do point it at production, it never writes, never modifies data, and never blocks a query — it observes through the same protocol your application uses.
How is it different from pg_stat_statements?
pg_stat_statements gives you raw counters. Tern takes those counters and turns them into decisions: it normalises query shapes, estimates rows scanned versus rows returned, joins the plan, proposes specific index DDL, and ranks everything by total time wasted rather than by call count. Tern also works with MySQL, SQLite, and MongoDB.
Will the suggested indexes slow down writes?
Every suggestion Tern prints includes its write cost — index size, expected maintenance overhead, and a rough insert/update delta. Suggestions over your configured threshold are downgraded to "informational" and excluded from the ranked list by default.
Can I use it in CI?
Yes. Run tern check --baseline tern.yml in your workflow. It spins up a throwaway database, applies your migrations, replays your test suite, and exits non-zero if any query exceeds the committed latency budget. The GitHub Action handles setup for you.
Does it support ORMs like Prisma or Django?
Tern sits at the database layer, so it is ORM-agnostic. On top of that it ships source-location hints for common ORMs — Prisma, Django, SQLAlchemy, Rails, Drizzle, TypeORM — so each slow query is linked back to the file and line that issued it.
Is Tern open source?
The CLI is MIT-licensed and free for unlimited use, including commercial teams. Tern Cloud is an optional hosted service that stores baselines across repos, schedules nightly traces, and posts PR comments — it's free for open-source projects.
