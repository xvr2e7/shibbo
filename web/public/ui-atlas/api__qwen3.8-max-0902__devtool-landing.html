01 METHOD

Install to indictment in three moves.

Tern never touches your workload. It reads the accounting your database already keeps, then does the reading for you.

  1. 01 Point it at the database
  2. 02 Scan the fleet
  3. 03 Ship the fix
STEP 01

tern init

Detects the engine, verifies read-only access, snapshots a baseline. No extension, no migration, no restart.

$ tern init postgres://prod-ro@db1/app
✓ engine detected: PostgreSQL 16.3
✓ pg_stat_statements: enabled (top 5000)
✓ baseline captured → .tern/base.snap
STEP 02

tern scan

Samples the stats views across a window, fingerprints every query, ranks by total time, p95 and lock wait — then annotates the plans.

$ tern scan --window 5m --top 10
sampled 4,218 fingerprints · 1.9M executions
▲ ranked by: total_time · p95 · lock_wait
✓ 3 offenders over budget (p95 > 250ms)
STEP 03

tern fix --suggest

Proposes indexes and rewrites, then verifies them against EXPLAIN on a replica before it recommends anything. You copy one line; p99 goes down.

CREATE INDEX idx_items_order
  ON order_items (order_id) INCLUDE (sku);
-- plan cost 18432 → 214 · verified ✓
